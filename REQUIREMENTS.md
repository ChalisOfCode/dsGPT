# Preserved product requirements

This public summary preserves the product scope without publishing personal
conversation transcripts, private hardware reports or the original personal brief.
The complete original brief and historical evidence remain in the private archive.
Public development does not replace the local-inference requirement.

| Area | Required behavior |
| --- | --- |
| Installation | Usable Windows EXE and Android APK; automatic free dependency/runtime setup, accurate progress, reboot recovery, no unnecessary Ollama account/onboarding, no destructive reinstall. |
| Models | Local inference, reviewed normal and abliterated options appropriate to available resources, clear model/context/reasoning controls, honest capability and performance limits. No paid inference fallback. |
| Chat interface | Consistent Chat/Work switch, composer with visible typed text, model/effort selectors, live dictation text, streaming and controllable auto-scroll, generated titles, sidebar, new/rename/pin/hide/delete chat and chat files. |
| Long requests | Preserve original prompts and file bytes; page/retrieve large requirements and evidence with hashes; avoid overflowing context with internal research/tool metadata; never silently discard requested requirements. |
| Research | Search, retrieve, cite and refine through an ongoing research loop, with source management, bounded context, interruption recovery and honest blocked-site reporting. |
| Memory/history | Persistent conversations and scoped memory; history import, provenance, duplicates/versions, deliberate memory promotion, related-project grouping with editable associations. |
| Autonomous Work | Plan, research, edit, compile, inspect failures, repair, test, deliver real APK/EXE/files; persistent pause/resume/cancel/restart; useful rereads after changes, bounded repeated failure detection; keep Chat usable while Work runs. |
| Existing software | Import, inspect and modify supported APK/EXE/project formats, preserve originals, package identities/data/signing where applicable, report unsupported binary modification rather than fabricate success. |
| Files/media | Large bounded originals, text/image/Office extraction, vision when supported, audio/video inspection, long-recording windows and checked combined transcripts, document rendering and real spreadsheet recalculation. |
| Account tools | Explicit scoped signed-in sessions, protected credentials, owner login/MFA handoff, task/device authorization, revocation and interrupted-write recovery. No credential leakage to model or diagnostics. |
| Devices | Secure paired phone access over Tailscale, automatic reconnect after upgrades, lifecycle/background recovery and data preservation; wireless debugging only for optional installation/diagnostics, not normal chat. |
| Diagnostics | Correlated, bounded desktop/mobile events and reviewed exports, redaction, model/context/empty-output diagnosis; no automatic public upload of personal reports. |
| Safety/integrity | Authenticated APIs, isolated tool workspaces, safe files/URLs, protected secrets, no public ports/Funnel by default, preserve existing software/data, verifiable artifact and source hashes. |
| Delivery | Real tested binaries with version/checksums, Android signing continuity, truthful Windows signing status, tested upgrade behavior, explicit limitations. |

   including a follow-up modification and independent artifact/native checks.
2. Protected signed-in website/account workflows and controlled real-browser tests.
3. Independent document layout/render checks and actual workbook formula calculation.
4. Editable related-project grouping that preserves originals and permissions.
5. Empty-response diagnosis, software upgrade preservation and reconnect checks.
   Disposable Windows/Android tests are required; physical PC/Pixel/GPU observations
   are optional targeted tests and must remain labeled unverified when unavailable.

Do not deliver another upgraded ZIP until this software scope is completed. The
2026-11-03 instruction removes owner hardware and the local worker from the routine
development/release path; it does not waive actual software tests or signing/data
continuity. See the completion plan for detailed acceptance criteria and status.
